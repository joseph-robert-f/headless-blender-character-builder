# v0.1 Decision Ledger

Status: adopted for the local v0.1 release candidate.

The decisions below record the binding defaults from `PLAN.md` Section 17. Contract changes require corresponding documentation and tests.

| ID | Decision | Adopted value | Rationale |
|---|---|---|---|
| D-001 | Project identity | **Headless Blender Character Builder**, slug `headless-blender-character-builder` | Neutral and descriptive |
| D-002 | Source license | GPL-3.0-or-later | One clear GPL-compatible license for Blender-linked source |
| D-003 | Sample license | CC0-1.0, declared separately | Original example artwork remains distinct from source licensing |
| D-004 | Default example | Original `facet-bot` geometric desk-toy robot | Avoids third-party characters and product branding |
| D-005 | Required artifacts | `.blend`, GLB, STL, preview, front/side/back diagnostics, manifest, and QA | Editable geometry plus portable formats and evidence |
| D-006 | Print claims | Geometry diagnostics only; no physical-print warranty | Printer, material, slicing, calibration, and handling remain external |
| D-007 | AI/MCP | Post-v0.1 adapter; no OpenAI dependency in the critical path | Keeps the builder deterministic and keyless |
| D-008 | Release platform | `linux/amd64`; native macOS and Docker Desktop are contributor/evaluator paths | Matches the pinned release-container requirement |
| D-009 | Local modes | One-shot synchronous builder first; asynchronous Compose service second | Preserves a small, keyless evaluation path |
| D-010 | Service stack | FastAPI, Postgres, Redis, and MinIO behind replaceable interfaces | Provides durable local operation without coupling generator code |
| D-011 | Cloud scope | Validated VPS package in v0.1; managed-cloud templates later | Makes deployment concrete without paid infrastructure |
| D-012 | Public artifacts | Source-first repository; generated outputs ignored; no Git LFS in v0.1 | Keeps clones small and prevents local metadata leakage |
| D-013 | Governance | DCO sign-off and maintainer review; no CLA | Low-friction contribution model consistent with GPL source |
| D-014 | Windows/WSL2 | Experimental and non-release-blocking in v0.1 | No verified Windows environment is available for the release gate |
| D-015 | Contract identifiers | `build/v1`, `character/v1`, `qa/v1`, `manifest/v1`, and `geometric-character@1.0.0` | Keeps request, evidence, and generator evolution explicit |
| D-016 | Canonical hashing | Strict UTF-8 JSON, bounded decimal parsing, sorted object keys, normalized numeric forms, expanded defaults, and SHA-256 | Makes semantically equivalent requests share stable request/spec hashes |
| D-017 | QA status authority | JSON Schema enforces structure and directly expressible pass constraints; the pure-Python model is normative for cross-field arithmetic and status derivation | JSON Schema cannot express the required per-axis tolerance arithmetic without custom extensions |
| D-018 | Unknown mandatory QA | `needs_review`, application exit `11`, and no success manifest | Unmeasurable evidence must never be treated as a successful build |
| D-019 | Unit and tolerance contract | Published dimensions use millimeters; height and GLB/STL bounds use `max(0.2 mm, 0.5%)` per applicable axis | Aligns all modes and round-trip verification with `PLAN.md` Section 8 |
| D-020 | Python and schema validation | Project Python is 3.11+; production contract models remain standard-library-only; `jsonschema==4.26.0` is a test extra | Blender 4.5 bundles Python 3.11 while a real Draft 2020-12 engine remains part of the gate |
| D-021 | Blender version provenance | Record the exact bounded `bpy.app.version_string`, currently `4.5.12 LTS` | Avoids silently dropping the LTS designation from native and container manifests |
| D-022 | Generated scene representation | Preserve separate display meshes in `CHARACTER` and derive exactly one hidden printable shell in `PRINT`; total requested height includes the exact display base | Keeps editable evidence distinct from the watertight manufacturing-oriented union |
| D-023 | Generator determinism evidence | Compare canonical structural reports across two fresh processes per fixture and require a palette-independent geometry signature plus topology differences across fixtures | Proves repeatability and schema-driven geometry without promising byte-identical Blender files |
| D-024 | Semantic geometry rejection | Reject schema-valid but impossible height/base layouts before factory reset or any scene mutation | Keeps request/policy failures separate from Blender generation side effects |
| D-025 | Tail component compatibility | `stub-tail` and `swept-tail` are mutually exclusive in both JSON Schema and runtime validation, with a generator preflight guard | Prevents ambiguous double-tail composition and any partial-scene name collision |
| D-026 | Native artifact publication | Accept exactly `--request` and `--output`; require a nonexistent output; use a private mode-`0700` sibling stage, fixed exporters/renders, a fresh child verifier, success manifest last, and atomic rename | Prevents partial or caller-shaped publication and keeps one trusted artifact contract for later container/service adapters |
| D-027 | Conservative actual-shell thickness evidence | Measure every final-shell triangle with strict opposing/reciprocal rays; deduct two voxel widths; treat any unresolved short candidate or ray miss as unknown; confirm allowlisted semantic features from final-shell cross-sections plus the same uncertainty deduction | Avoids both metadata-only print claims and false success when post-union geometry is ambiguous |
| D-028 | Reviewed palette persistence | Convert declared sRGB hex colors to Blender scene-linear inputs and mark every reviewed material with a fake user | Keeps renders faithful and prevents an unused declared swatch from disappearing across save/reload and changing provenance |
| D-029 | Diagnostic lighting | Use fixed 512 px, 32-sample Eevee views with shadow-free area lights | Removes shadow-map stippling at intentionally overlapping display solids while geometry/topology remain independently verified |
| D-030 | Printable-shell connectivity | Count shells by face adjacency through shared edges and require zero non-manifold vertices as well as zero non-manifold edges | Rejects bow-tie or vertex-pinched meshes that vertex-only connectivity can misclassify as one printable manifold shell |
| D-031 | Container output mount | Supersede the precreated `build/demo` sketch in `PLAN.md` Section 5: mount the caller-owned `build/` parent at `/output` and require final `/output/demo` not to exist | Preserves the G3 private sibling-stage plus atomic-rename contract; mounting `build/demo` itself would make atomic publication impossible |
| D-032 | Builder image supply chain | Pin the Debian base by digest and snapshot date, verify the official Blender 4.5.12 archive checksum, keep production Python dependency-free, hash-lock test wheels, and bake notices plus an SPDX 2.3 SBOM | Makes the keyless image rebuild auditable without trusting floating system or Python dependencies |
| D-033 | One-shot resource envelope | Limit each build or verifier container to 4 CPUs, 4 GiB RAM, 512 PIDs, and a 2 GiB no-exec scratch tmpfs | Passed the reference artifact under emulation while leaving host overhead within the recommended 8–16 GiB development capacity |
| D-034 | Service isolation from the builder | Keep service orchestration under `service/` and outside the fixed G4 source-revision inputs; derive a separate supervisor image later without replacing the inherited builder entrypoint or artifact contract | Preserves the already-gated deterministic image while allowing API/worker dependencies to evolve independently |
| D-035 | Durable authority and queue wakeups | PostgreSQL is authoritative and writes queue intent through a transactional outbox; Redis Streams carries exactly one canonical build UUID and provides at-least-once wakeups only | Prevents queue loss or duplicate delivery from becoming job-state corruption and keeps requests/secrets out of Redis |
| D-036 | Immutable service artifact evidence | Generate attempt-scoped allowlisted keys, require object-store versioning, hash both the exact upload stream and stored version body, persist the version ID, publish `manifest.json` last, and sign the exact stored version | Caller-supplied metadata, ETags, overwrites, or races cannot silently substitute bytes after success |
| D-037 | Opaque builder progress | Reserve `geometry_qa` and `rendering` but allow verified publication directly from `running`; emit an optional stage only when the supervisor has real trusted evidence | The G4 builder exposes a terminal result, so fabricated intermediate status would be misleading |
| D-038 | Local secret roles | Generate distinct admin, API, worker, and migrator database/storage credentials; map only each process's scoped values to generic runtime settings and keep provider keys absent | Lets Compose enforce least privilege without making `.env` a direct all-secrets process environment |
| D-039 | HTTP submission semantics | Authenticate before parsing, stream at most 64 KiB, return `202` for a new build and `200` for an exact idempotent replay, and apply `no-store` plus a server request ID to every response | Keeps the API asynchronous, bounded, replay-safe, and free of caller-controlled correlation IDs |
| D-040 | Attempt authority and fencing | PostgreSQL owns leases, heartbeats, cancellation, retry exhaustion, recovery, and terminal publication; every attempt mutation requires a hashed random lease fence | Duplicate or reclaimed Redis deliveries cannot create two active attempts or publish stale work |
| D-041 | Supervisor process boundary | Leave the immutable G4 builder revision unchanged; in the derived service layer, launch one fresh wrapper per attempt and freeze/terminate its bounded Linux `/proc` descendant tree across separate process groups before scratch cleanup | The inherited builder starts Blender in a new session, so killing only the wrapper group can orphan Blender |
| D-042 | Queue and outbox recovery | Reclaim stale Redis pending entries with bounded `XAUTOCLAIM`; use forward migration `0002_g6_outbox_counter` and a saturating bigint domain for dispatch evidence | Recovers both the claim-before-lease crash window and Redis outages lasting beyond the original 100-attempt smallint limit |
| D-043 | Public artifact signing | Construct separate internal and public MinIO clients with the fixed local region `us-east-1`; use the public client only for pure-computation signing and the internal client for bucket/object operations | Prevents the API container from trying to discover bucket location through its host-facing `localhost` URL |
| D-044 | Service observability | Emit bounded JSON Lines with allowlisted IDs, codes, booleans, and counts; omit requests, child log tails, credentials, endpoints, and signed URLs | Provides lifecycle evidence without turning logs into a secret or customer-input sink |
| D-045 | Local S3 compatibility fixture | Source-build MinIO Community `RELEASE.2025-10-15T17-29-55Z` at commit `9e49d5e7a648f00e26f2246f4dc28e6b07f8c84a` with pinned Go, source, client, Debian snapshot, and checksums; label it local-development-only and require a maintained managed/operator S3 service for production | The old registry image predates the final security release, while the successor distribution requires a proprietary account/license and cannot be the repository's zero-account redistributable default |
| D-046 | Local Compose network topology | Put state, queue, storage, API, and worker on one internal network; attach only API and MinIO to a second bridge whose published ports bind to host loopback; keep the worker solely internal | Preserves host API/download access without giving the Blender supervisor a default public route or exposing databases |
| D-047 | Local privilege convergence | On every start, revoke accumulated PostgreSQL memberships, current privileges, and API/worker defaults on future migrator-owned tables/sequences; reapply explicit role grants; inventory and remove every reserved current/legacy MinIO identity before recreating the configured pair and fixed policies without deleting bucket data or object versions | Repeat starts and credential rotation converge to least privilege instead of silently accumulating authority or destroying durable artifacts |
| D-048 | Production storage boundary | Disable the bundled MinIO fixture in the VPS package; require an operator-maintained, versioned S3-compatible service on a private network; configure distinct internal object-operation and public signed-download endpoints with explicit TLS and region values | Keeps the local compatibility fixture out of production while allowing API/worker traffic to stay private and clients to receive publicly reachable exact-version URLs |
| D-049 | Maintenance and recovery authority | Use distinct maintenance database and storage identities; grant only the tables, columns, sequences, namespace prefix, and exact-version operations required for preview/apply retention, durable deletion evidence, quiesced backup, empty-target restore, and Redis reconstruction | Makes lifecycle work explicit and auditable without giving API, worker, or maintenance processes general database administration or bucket-wide deletion authority |
| D-050 | VPS operator trust and serialization | Require digest-locked releases, root-owned non-group/world-writable trust inputs and ancestor directories, a persistent fail-fast `fcntl` operator lock, and a single-namespace database invariant for writable lifecycle and backup actions | Prevents untrusted configuration substitution, concurrent destructive maintenance, Compose project drift, and cross-namespace recovery mistakes |
| D-051 | Forward-only upgrade handoff | Persist a target-bound `preparing` → `ready` → `upgrading` handoff before the target can write or migrate; once `upgrading` begins, forbid source abort and allow only the exact target retry or a marker-bound empty-target rollback from the verified backup | Forward migrations cannot be safely undone in place, so a failed transition must remain recoverable without split authority or an implicit database downgrade |
| D-052 | Pinned MinIO version-delete compatibility | Alongside `s3:DeleteObjectVersion`, allow `s3:DeleteObject` only when the pinned local fixture supplies a UUID-shaped `s3:versionid`; keep unversioned deletion denied and require provider-specific IAM validation in production | The pinned MinIO single-object handler checks `DeleteObject` even for an exact version, while its empty version value lets the condition preserve the intended no-unversioned-delete boundary |
| D-053 | Executable modes across Git checkouts | Gate tracked operator scripts on executable bits and absence of group/world write access, then install production copies as root-owned mode `0555` | Git preserves executability but cannot encode exact read/execute permission bits, so clean checkouts commonly materialize safe `0755` files before hardened installation |
| D-054 | Public model evidence | Track only a 384×384 optimized PNG derived from the passing real-Blender service render, with a CC0 per-file manifest binding the original artifact, build manifest, QA, generator, Blender version, transformation, byte size, and SHA-256 | Makes the README visually useful while proving the image came from an inspectable model and keeping the source clone small and rights-clear |
| D-055 | Release source of truth | Audit the final Git index, require an exact `git checkout-index` export, and package that pristine export separately from the disposable tree used to run builds and services | Staged publication intent is reviewable before a milestone commit, while generated `.env`, service state, and test artifacts can never leak into the source archive |
| D-056 | Service SBOM and notice delivery | Generate deterministic builder/API/worker SPDX 2.3 documents offline from the actual builder SBOM, checksum-locked service requirements, and a reviewed license inventory; embed human notices and reviewed inventories in service images and attach normalized SBOMs to the local release bundle | Keeps third-party inventory reproducible without network metadata lookup and covers both the Blender-bearing supervisor and the Blender-free API image |
| D-057 | Fork-safe CI syntax and trust | Author workflow files as JSON-form YAML, validate them with the Python standard library, pin every external action to a full commit SHA, disable persisted checkout credentials, use read-only token permissions, and never use `pull_request_target` or self-hosted runners for contributor code | Provides dependency-free syntax validation and an auditable minimum-permission fork boundary |
| D-058 | Local versus published release identity | Produce `0.1.0-rc.1` builder/API/worker tags, normalized local image IDs, sample artifacts, SBOMs, metadata, and checksums locally; require separately authorized GHCR pushes, registry digests, signed Git tags, and GitHub Release publication | A local release gate can prove bytes and configuration without credentials or irreversible external effects, while production deployment still binds immutable registry digests rather than mutable tags |
| D-059 | Production and test dependency boundary | Keep production API/worker Python dependencies separately hash-locked and copy test-only HTTP clients into only the service-test target; give executable scratch space only to that private test target | Prevents release helpers from expanding the production runtime while still allowing Linux subprocess and integration fixtures to execute under the container gate |
| D-060 | Production image mode normalization | After every production copy, recursively remove write bits and add only required read/traverse bits; retain a private mode-`0700` work directory owned by UID/GID `65532` | Makes final runtime permissions independent of builder umask and ensures the unprivileged process can import code without being able to mutate installed source, provenance, notices, or dependencies |
| D-061 | GLB repeatability evidence | Compare decoded GLB structure, topology, materials, transforms, and bounds across fresh builds, but exclude encoded container byte length and accessor-table cardinality from the structural fingerprint; continue to hash, frame-check, and fresh-import each individual GLB artifact | Blender 4.5.12 may deduplicate an otherwise identical index accessor across exports: retained 49- and 50-accessor GLBs produced the same decoded semantic fingerprint, so encoder representation is not a scene-semantic property while authenticity and validity remain independently proven for every delivered file |
| D-062 | Scoped clean-export umask | Keep release scratch roots and the wrapper default at mode/umask `0700`/`077`, but run each `git checkout-index` materialization in a subshell with umask `022` before independently validating tracked modes | Preserves private temporary state while allowing Git executable bits to materialize portably as non-group/world-writable `0755` instead of host-specific `0700` |
| D-063 | Cancellation fixture readiness | In the nested-process cancellation test, publish a separate readiness sentinel only after the PID inventory write has closed; request cancellation only after that sentinel | Removes a test-only create-before-write race and proves production process-tree termination without weakening or changing launcher behavior |
| D-064 | Source versus container publication | Allow the source repository/tag and source/sample assets to proceed through their own release gates, but block public OCI pushes until an exact image-by-image corresponding-source inventory, delivery method, checksums, and retention policy are independently reviewed | Blender-bearing images and other binary components create redistribution duties that are not proven by an upstream link or Dockerfile alone; source publication need not be held behind unresolved container distribution mechanics |
| D-065 | Maintainer-controlled dependency audit | Remove repository-configured Dependabot version-update rewrites; add an offline synchronization gate, a scheduled/manual read-only freshness and checksum-pinned OSV scan, and an offline wheel-to-lock candidate helper; retain size-capped reports but grant the workflow no dependency branch, issue, pull-request, registry, or security-event write permission | Dependency versions are coupled to hashes, licenses, notices, image provenance, recovery fixtures, and migration policy, so discovery can be automated while selection and coordinated evidence remain reviewed maintainer work; repository-level Dependabot security updates remain a separate owner setting |

## Recorded execution conditions

- The repository already has an explicitly authorized public `origin`; this supersedes the initial-plan preference for no remote during M0. The build goal does not authorize further remote pushes, image publication, releases, DNS changes, paid services, or live deployment.
- Native Blender is resolved from the macOS application bundle because `blender` is not on `PATH`. Container and CI contracts continue to use the standard `blender` executable path inside the image.
- Live VPS HTTPS and physical-print trials remain conditional. Local configuration validation and a recovery drill remain release-blocking.
