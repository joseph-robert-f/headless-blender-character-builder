# Headless Blender Character Builder v0.1.0-rc.1

This is the first source-first release candidate for a bounded, local-first
headless Blender character pipeline.

## Supported scope

This v0.1 release candidate supports one trusted user building their own models locally with the
one-shot Docker builder. A trusted user controls the machine and creates or
reviews the bounded JSON request. The optional Compose service is experimental,
loopback-only, and intended for one trusted operator. Internet-facing,
multi-tenant, and VPS operation are outside this release's supported scope.

## What works

- A no-key, single-container `make demo` path builds real Blender geometry from
  strict JSON and publishes `.blend`, GLB, STL, four renders, QA, and a
  hash-bound artifact manifest.
- `make verify-demo` starts another fresh Blender process, reloads the scene,
  imports GLB/STL, and rechecks geometry and hashes.
- The experimental local Compose service provides authenticated asynchronous
  submission, durable PostgreSQL state, Redis delivery/recovery, versioned
  artifacts, cancellation, idempotency, and a concurrency-one worker.
- The out-of-scope VPS reference exercises Caddy HTTPS, digest locks, bounded
  resources and logs, external S3 guidance, retention, quiesced backup/restore,
  and forward-only upgrade recovery for future design work.

## What this is not

This is not unrestricted prompt-to-3D, an organic sculptor, a hosted SaaS, a
public or multi-tenant service, a supported VPS deployment, a Pokémon or
protected-character generator, or a physical-print guarantee. It does not
execute user Python, accept add-ons or uploaded `.blend` files, fetch remote
references, or require OpenAI/MCP.

## Platform

The release image is `linux/amd64`. Docker Desktop on Apple Silicon is a tested
evaluation path through emulation. Linux `arm64` and Windows/WSL2 are not
release-blocking in this candidate.

## Upgrade and compatibility

The request, QA, manifest, and generator contracts are separately versioned.
There is no prior public application release to migrate. Service database
migrations are forward-only; follow the backup and target-bound upgrade
handoff in `docs/deployment.md`.

## Local release gate

The complete local candidate passed `make release-check` from the final intended
Git index on August 3, 2026. The gate rebuilt and fresh-verified the real Blender
sample, exercised the asynchronous service and recovery path, generated
builder/API/worker SBOMs, audited the 210-file source set, and produced a
checksum-verified local release bundle without a remote operation.

That August 3 record predates the release and lifecycle hardening summarized
below. It is historical evidence only. This candidate requires a new
final-commit `make release-check`; the pull request verification record, rather
than this tracked file, must name that run so recording it cannot change the
commit it attests.

GitHub-hosted native `linux/amd64` CI, registry digests, GitHub license detection,
image signing/publication, signed tag and Release creation, and any live VPS
smoke remain explicit operator actions. GitHub private vulnerability reporting
was enabled and verified on August 4, 2026.
The current candidate gate binds all builder/API/worker tags and OCI labels to this
distribution version and the exact audited commit. It also packages the exact
checksum-verified Blender 4.5.12 source archive, project source, dependency
inventories/notices, and a machine-readable, image-bound source record under one
`SHA256SUMS`. That record covers project and Blender source only and explicitly
marks public OCI readiness false. Public image publication remains blocked until
an independent actual-image review adds the source/delivery coverage required
for every applicable native, base-image, and copyleft component and the release
transaction inventories, SBOMs, signs, publishes, and locks the derived
PostgreSQL image alongside the builder, API, and worker images.
